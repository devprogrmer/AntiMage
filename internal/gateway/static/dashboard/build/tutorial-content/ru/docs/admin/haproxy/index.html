      Общие порты HAProxy

      AntiMage может запускать HAProxy на выбранных узлах и распределять соединения, пришедшие на один публичный TCP-порт, между несколькими назначениями. HAProxy анализирует начало соединения, сопоставляет SNI, HTTP Host или HTTP Path и передаёт исходный TCP-поток нужному входящему подключению Xray, внешнему сервису или сайту. Для маршрутов Xray он не расшифровывает трафик.

      Открыть HAProxyПроверить доступность входящих подключенийУстранение неполадок

      После включения конфигурации публичный порт занимает HAProxy. На том же адресе и порту не должны слушать Xray, Nginx, Apache, OpenVPN или другой процесс. Каждому Xray inbound нужен собственный backend-порт, отличный от публичного.

      Как устроена конфигурация

      1. Конфигурация содержит общие расширенные параметры и один или несколько целевых узлов.
      2. Целевой узел — узел AntiMage, где будет работать конфигурация.
      3. Listener — публичный TCP-адрес и порт узла, например 0.0.0.0:443.
      4. В listener находятся маршруты и необязательные сайты. Маршруты направляют трафик в Xray или TCP-сервисы; сайты обслуживают обычный HTTP/TLS.

      Можно создать несколько конфигураций HAProxy. Один узел может принадлежать только одной из них, но конфигурация может включать много узлов. На каждом узле допускается до 16 listener; у каждого собственные маршруты и сайты. Агент AntiMage проверяет файл командой haproxy -c до замены активной конфигурации. Установка и обновление агента, а также образ Docker уже включают HAProxy.

      Перед настройкой

      • Обновите мастер-панель и все целевые узлы до версии с поддержкой HAProxy.
      • Проверьте, что публичные TCP-порты свободны: ss -lntp на каждом узле.
      • Откройте TCP-порты в firewall узла и у провайдера.
      • Для каждого Xray inbound задайте отдельный локальный backend-порт.
      • Определите, по какому видимому признаку различать соединения: уникальный SNI, HTTP Host или HTTP Path.
      • Сохраните доступ к управлению узлом: ошибочное правило listener/firewall не должно блокировать SSH.
      • Сначала сохраните выключенный черновик, проверьте вывод вкладки Editor и только затем включайте конфигурацию.

      Быстрая настройка: несколько сервисов на порту 443

      Входящий трафикПроверкаНазначение
      VLESS RealitySNI edge.example.comXray на 127.0.0.1:5424
      VLESS WebSocketHTTP Path /ws-mainXray на 127.0.0.1:5425
      Обычный HTTPSSNI www.example.comСайт с сертификатом панели
      1. Подготовьте на целевом узле два Xray inbound с разными портами, тегами и параметрами распознавания.
      2. Откройте HAProxy и выберите Create HAProxy.
      3. Задайте имя конфигурации. Пока выключите Enabled.
      4. Выберите узел и нажмите Add target.
      5. Для listener-1 оставьте адрес 0.0.0.0 и укажите публичный порт 443.
      6. Выберите Reality inbound в Compatible Xray inbound, задайте matcher SNI и нажмите Add inbound.
      7. Добавьте WebSocket inbound с путём /ws-main.
      8. Нажмите Add website, включите сайт, укажите www.example.com, выберите Certificate from panel SSL и активный подходящий сертификат.
      9. Выберите встроенный шаблон, TemplateMo или загруженный статический шаблон.
      10. Откройте Editor: AntiMage проверит черновик и покажет файл HAProxy для узла.
      11. Вернитесь в Form, включите конфигурацию и нажмите Save.

      Проверяйте каждую ветвь отдельно. Успешный ответ сайта подтверждает только маршрут сайта, но не маршруты VLESS.

      Как HAProxy определяет соединение

      Все listener работают в TCP-режиме. После заданной задержки HAProxy проверяет доступные первые байты соединения.

      МетодЧто читаетсяТипичное применение
      sniИмя узла в TLS ClientHelloTLS, Reality, сайты HTTPS и TLS-сервисы
      http_hostЗаголовок HTTP HostHTTP-транспорты с разными именами хостов
      http_pathНачало пути HTTP-запросаWebSocket, HTTPUpgrade, SplitHTTP и другие HTTP-транспорты с уникальным путём
      defaultСигнатура не задана; маршрут получает трафик, который не подошёл раньшеОдин непрозрачный протокол или резервный сервис

      Для Xray и внешних маршрутов проверка SNI не завершает TLS: HAProxy читает ClientHello и передаёт исходное соединение backend-серверу. Для сайта иначе: локальный веб-сервер узла завершает TLS выбранным сертификатом.

      В пределах одного listener пары matcher должны быть уникальны. Допускается не более одного маршрута default. SNI сайта не может совпадать с SNI-маршрутом на том же listener. Зашифрованные потоки без видимого SNI, Host или Path для HAProxy неразличимы: используйте отдельные порты либо один из них как default.

      Доступные Xray inbound

      Список создаётся по реальной конфигурации Xray выбранного узла. Для inbound нужны непустой тег, допустимый порт и распознаваемый matcher; AntiMage извлекает его из streamSettings.

      Транспорт или безопасностьMatcherТребование
      Обычный WebSocket, HTTPUpgrade, SplitHTTP и другие HTTP-транспортыhttp_pathВ настройках транспорта задан непустой путь.
      Обычный HTTP с Host или headers.Hosthttp_hostУказано допустимое уникальное имя хоста.
      TLS-транспорт с HostsniУказано допустимое уникальное имя.
      TLS с tlsSettings.serverNamesniЗадано допустимое уникальное имя сервера.
      Reality с realitySettings.serverNamesОтдельный вариант sni для каждого имениВыберите имя, которое действительно отправляет клиент.
      Не-Shadowsocks inbound без этих значенийdefaultНа listener может быть только один маршрут по умолчанию.
      ShadowsocksМаршрут по PathПуть транспорта обязателен; без него inbound скрыт из списка.

      Если inbound отсутствует в списке, проверьте тег, порт в диапазоне 1–65535, отличие backend-порта от публичного, наличие Path у Shadowsocks и то, что параметры присутствуют в сгенерированной конфигурации Xray именно этого узла. Inbound не должен быть уже добавлен в этот listener; настройки цели должны быть раскрыты.

      Поля вкладки Form

      Конфигурация и целевой узел

      ПолеНазначение
      Configuration nameВнутреннее имя панели длиной до 128 символов; оно не меняет домен, тег Xray или имя frontend.
      EnabledПрименяет созданную конфигурацию на всех целевых узлах. Выключите, чтобы оставить черновик без запуска HAProxy.
      Target nodeВыбор узла. Отключённые узлы недоступны; узел, уже принадлежащий другой конфигурации, выбрать нельзя.
      Add targetДобавляет карточку узла с одним listener. Нужен хотя бы один узел; максимум — 256.
      Template name / ZIP / UploadДобавляет статический шаблон. ZIP должен содержать index.html, только безопасные статические файлы и занимать не более 32 MiB; распакованное содержимое — до 128 MiB.
      Show settingsСворачивает или раскрывает карточку. Это меняет только интерфейс, а не состояние узла.
      Clone to all available nodesКопирует listener, маршруты, сайты и параметры на активные свободные узлы.

      Копирование строгое: на целевом узле должны существовать такой же тег Xray inbound и такая же пара типа/value matcher. Backend-порт берётся из конфигурации конкретного узла. Если обязательный inbound отсутствует, целевая карточка пропускается с предупреждением. Отключённые узлы не копируются.

      Параметры listener

      ПолеНазначение
      Listener nameВнутренняя однострочная подпись длиной до 64 символов.
      Listen addressЛокальный адрес узла. 0.0.0.0 — все IPv4-адреса, :: — IPv6; конкретный IP ограничивает привязку.
      Public portTCP-порт для клиентов, диапазон 1–65535. На одной цели нельзя повторить тот же адрес и порт.
      Accept incoming PROXY protocolТребует корректного заголовка PROXY от клиента или балансировщика. Для обычных прямых подключений оставьте выключенным.
      Compatible Xray inboundПоказывает только обнаруженные на выбранном узле inbound: тег, протокол, сеть и matcher.
      Add inboundДобавляет маршрут на 127.0.0.1 и фактический порт inbound; backend берётся из конфигурации узла.
      Add external serviceДобавляет TCP backend для OpenConnect, OpenVPN TCP, локального сервиса или другого назначения вне Xray.
      Add port / listenerДобавляет отдельные адрес и порт с собственной таблицей маршрутизации.

      На цели допускается до 16 listener; на одном listener — до 32 маршрутов и 16 сайтов. Нужен хотя бы один маршрут или включённый сайт.

      Внешние сервисы и сайты

      Для внешнего маршрута задаются уникальное имя, доступный с узла backend-хост и TCP-порт, метод распознавания (sni, http_host, http_path, default) и значение. Путь должен начинаться с / и не превышать 512 символов. Хост должен быть допустимым, порт — в диапазоне 1–65535; маршрут и пара matcher должны быть уникальны.

      Сайты необязательны и обслуживают обычный HTTP/TLS на общем порту. Узел отдаёт статические файлы, а HAProxy подключается к локальному сайту через Unix-сокет; дополнительный публичный порт не открывается.

      Параметр сайтаНазначение
      Включение сайтаВыключенный сайт не попадает в конфигурацию, но его параметры сохраняются.
      Default HTTP/HTTPS websiteДоступен только для первого сайта. Получает нераспознанный HTTP/HTTPS после маршрутов; несовместим с default-маршрутом на listener.
      Имя сайтаВнутренняя подпись до 64 символов; если пусто, используется домен.
      Hostname / SNIИмя для HTTP Host или TLS SNI. Для сайта по умолчанию необязательно; для других TLS-сайтов обязательно.
      TLS certificateОбычный HTTP, автоматически созданный self-signed сертификат, сертификат из панели SSL или файлы на узле.
      Template sourceВстроенная страница, TemplateMo или загруженный ZIP.
      Custom 404 HTMLСтраница ошибки только для этого сайта, до 64 KiB. Пустое поле включает обычный ответ статического сервера.

      TemplateMo URL должен использовать HTTPS, домен templatemo.com и путь /tm-NNN-name. Архив должен содержать index.html. PHP, WordPress, базы данных и другой код на сервере не выполняются — обслуживаются только статические файлы.

      Для TLS доступны режимы без TLS (HTTP), автоматический self-signed сертификат, сертификат панели SSL или абсолютные пути на узле к fullchain.pem и закрытому ключу. Браузер предупреждает о self-signed сертификате. Сертификат панели должен покрывать домен; агент безопасно передаёт PEM-данные при синхронизации. Для пользовательских путей проверьте наличие и права файлов на каждом узле.

      Editor, сохранение и копирование узлов

      Открытие Editor отправляет черновик backend для проверки и генерации. Редактор только для чтения и показывает итоговый файл HAProxy для каждого узла. После изменения формы нажмите Refresh. Перед включением проверьте bind, правила acl, use_backend, намеренный default_backend и правильный порт назначения каждого Xray.

      Save сохраняет черновик и ставит синхронизацию узлов в очередь. Включённая конфигурация применяется, когда узел получает новое состояние. Выключение и сохранение останавливает runtime HAProxy и локальные сайты этой конфигурации на целевом узле.

      Перед Clone to all available nodes настройте и проверьте один узел. Каждому целевому узлу требуются те же Xray-теги и точные matcher. AntiMage обновляет backend-порт по конфигурации Xray конкретного узла. Узел пропускается, если он выключен, уже используется, не может быть проверен или не содержит необходимого inbound. Можно копировать до 16 listener, включая разные публичные порты. Рандомизация меняет только выбор шаблонов TemplateMo.

      Совместимость с протоколами, кроме Xray

      Возможна маршрутизация TCP, если трафик содержит надёжный matcher.

      Протокол/сервисПоддержкаРекомендуемая настройка
      OpenVPN TCPДаОтдельный listener или единственный внешний маршрут default; обычно полезного SNI/HTTP Path нет.
      OpenVPN UDPНетTCP-listener HAProxy не принимает UDP.
      WireGuardНетWireGuard использует UDP; оставьте его порт вне конфигурации HAProxy.
      L2TP/IPsecНетИспользует UDP-порты, включая 1701, 500 и 4500.
      OpenConnect / AnyConnect TCP/TLSОбычноДобавьте внешний сервис. Используйте SNI, только если клиент отправляет уникальное имя; иначе отдельный listener или default. UDP-ускорение не поддерживается.
      SSH, база данных и другой TCP без сигнатурыДаОтдельный listener или default.
      HTTP/HTTPSДаhttp_host, http_path, sni или встроенный сайт.

      Имя маршрута и порт backend не позволяют HAProxy определить протокол. Для двух непрозрачных зашифрованных потоков нужны разные публичные порты.

      Практические схемы

      Два публичных порта на каждом узле

      • Listener public-443: 0.0.0.0:443, маршруты Xray по SNI/Path и HTTPS-сайты.
      • Listener vpn-550: 0.0.0.0:550, один внешний OpenVPN TCP-маршрут default.

      Создайте второй listener кнопкой Add port / listener. В поле Public port указывается только один порт: у каждого listener собственная таблица маршрутов.

      Несколько TLS-сайтов на 443

      Создайте listener 443, добавьте сайт для каждого домена и выберите сертификат. HAProxy направит соединение по SNI. Имена не должны совпадать с SNI Xray-маршрутов.

      VLESS WebSocket и обычный сайт

      Задайте WebSocket inbound уникальный путь, например /private-ws, и добавьте маршрут http_path. Затем добавьте обычный HTTP-сайт. Маршруты проверяются раньше сайтов: /private-ws попадёт в Xray, остальные подходящие запросы — на сайт.

      Один непрозрачный TCP-сервис как запасной маршрут

      Сначала добавьте все распознаваемые маршруты по SNI, Host и Path, затем укажите внешний сервис default. Весь нераспознанный трафик попадёт туда — используйте это только если такое поведение намеренно.

      Устранение неполадок

      ПроблемаЧто проверить
      В HAProxy нет доступных узловУзел выключен, удалён, уже выбран или принадлежит другой конфигурации.
      Не виден Xray inboundПроверьте тег, порт, назначение узлу и matcher. Для Shadowsocks обязателен Path.
      Дублирующий matcherНа одном listener совпали тип и значение двух маршрутов.
      Несколько маршрутов defaultОставьте один default либо первый сайт по умолчанию.
      Домен сайта конфликтует с маршрутомTLS-сайт и маршрут используют одинаковый SNI. Задайте разные имена.
      Не принимается сертификат панелиСертификат активен в SSL и покрывает домен сайта.
      Пользовательский сертификат не работает после копированияПути должны существовать на каждом узле; проверьте файлы и разрешения либо используйте сертификат панели.
      Загруженный шаблон не попадает на узелПанели нужен корректный ANTIMAGE_PUBLIC_URL; узел должен иметь выданный сертификат.
      Ошибка загрузки TemplateMoПроверьте исходящий HTTPS с узла и формат URL /tm-NNN-name.
      HAProxy отсутствуетОбновите или переустановите AntiMage Node.
      Порт уже занятНайдите процесс, слушающий адрес/порт; проверьте, что Xray inbound не использует публичный порт.
      Копирование узла пропущеноНа целевом узле должны совпадать тег inbound и точный matcher.
      Медленные клиенты попадают не тудаОсторожно увеличьте Inspection delay и проверьте фактический SNI, Host или Path клиента.
      Соединение закрывается через часПроверьте таймауты клиента и сервера; для длинных туннелей может потребоваться значение больше 3600 секунд.

      Ошибки проверки конфигурации, отсутствия пакета, загрузки шаблона, сертификата и привязки порта записываются в журнал AntiMage Node. Временно включайте debug, только если обычных сообщений недостаточно.

      Итоговая проверка

      • Каждый узел активен и принадлежит только этой конфигурации.
      • Публичные адреса и порты свободны.
      • У каждого Xray inbound отдельный backend-порт.
      • SNI, Host и Path уникальны на каждом listener.
      • На listener не более одного варианта по умолчанию: маршрут default либо первый сайт с ролью default.
      • Домены TLS-сайтов не совпадают с SNI маршрутов.
      • Сертификаты активны и покрывают нужные домены; локальные пути существуют на каждом узле.
      • Вывод Editor соответствует маршрутам всех узлов.
      • После сохранения отдельно проверен каждый вид трафика.
