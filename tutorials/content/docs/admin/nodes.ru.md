Для каждого узла в панели создаётся отдельная запись и комплект сертификатов mTLS. Создайте запись до запуска установщика: панели потребуется сформировать комплект для агента.

## Перед началом {#section-nodes-admin-intro}

- Выберите адрес узла и два разных порта. По умолчанию AntiMage использует порт агента `62050` и API Xray `62051`.
- Убедитесь, что основной сервер панели может подключиться к адресу и порту агента. По возможности разрешите доступ в firewall только с адреса панели.
- Синхронизируйте часы узла через NTP: от времени зависят проверка сертификатов и временные метки трафика.
- Решите, нужно ли умножать учитываемый трафик. Коэффициент `1` означает фактический расход; `2` удваивает учитываемый трафик пользователей узла.

## 1. Создайте запись узла в панели {#section-nodes-admin-guide}

1. Откройте **Node settings** и нажмите **Add node**.
2. Укажите понятное внутреннее имя и IP-адрес или имя хоста, доступное с главного сервера панели.
3. Установите **Node port** и **API port** в значения, которые будут указаны при установке. Они должны различаться.
4. Оставьте **Usage coefficient** равным `1`, если не требуется иной расчёт.
5. При необходимости задайте **Data limit** для узла. Пустое значение означает отсутствие ограничения.
6. Добавьте заметку. Включайте прокси от главного сервера к узлу только при необходимости.
7. Нажмите **Add node**. Панель создаст запись узла и отдельные сертификат и закрытый ключ.

{{< callout type="warning" >}}
Сразу скопируйте или скачайте весь **Node install bundle**. Он содержит сертификат и закрытый ключ. Не публикуйте комплект, не копируйте его частично и не используйте для другого узла.
{{< /callout >}}

## 2. Установите AntiMage Node на сервер узла

Запустите бинарный установщик на сервере узла:

```bash
curl -sL https://raw.githubusercontent.com/antimagepanel/AntiMage/master/scripts/antimage/antimage-node-binary.sh | sudo bash -s -- install
```

1. Когда установщик запросит **Node install bundle**, вставьте полный блок из панели. Сертификат и закрытый ключ будут разделены автоматически.
2. Укажите те же порт агента и API Xray, что и в записи узла.
3. Завершите установку и дождитесь запуска службы `antimage-node`.
4. Не устанавливайте один комплект на второй сервер. Для каждого дополнительного хоста создавайте отдельный узел в панели.

## 3. Проверьте соединение

Вернитесь в **Node settings** и дождитесь состояния **Connected**. Откройте узел, чтобы проверить адрес, порты, сертификат, версию Xray, CPU, RAM, пропускную способность и последние данные трафика.

Если статус остаётся Connecting или Error, проверьте:

| Проверка | Что проверить |
| --- | --- |
| Адрес и порты | Запись панели совпадает со значениями установщика; порты не перепутаны. |
| Маршрутизация и firewall | Главный сервер достигает порта агента, DNS указывает на правильный адрес. |
| Комплект сертификатов | Сертификат и закрытый ключ относятся именно к этому узлу. |
| Служба | `antimage-node` запущена; проверьте первое сообщение об ошибке в журналах службы. |
| Время | На обоих серверах установлено правильное время и работает NTP. |

## Переустановка или замена узла

Используйте существующую запись, если идентификатор узла должен сохраниться. Создавайте новый приватный сертификат непосредственно перед переустановкой агента с новым комплектом: старый сертификат больше не будет соответствовать панели. Для дополнительного сервера создайте отдельную запись узла.

{{< callout type="info" >}}
Обзор узла помогает отличить проблему соединения от ошибки Xray или нехватки ресурсов: сначала показаны состояние подключения и сообщение об ошибке, затем метрики.
{{< /callout >}}
